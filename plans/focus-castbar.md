# Focus cast bar implementation plan

Repository: `/Users/iu/wow/FocusClaim` (single writer). This plan implements the user's requested independent, movable focus cast bar without changing existing focus-click bindings.

## Settled behavior

- Default **off**. A setting toggles the bar. When on, show only while `focus` is casting or channeling; hide when no focus or the cast ends. A separate lock/unlock control permits dragging; save the position per character. Provide a reasonable fixed default width/height, without introducing size controls.
- Place a square spell icon immediately left of the bar, with side length equal to bar height. Render the spell name inside the left edge and remaining cast time on the right edge; avoid overlap. Account for casts and channels, including reversed channel progress. The bar fill/progress must move correctly.
- Automatically recognize the player's currently known primary interrupt, including pet interrupts and spec/spellbook changes. Grey when the cast cannot be interrupted; green when an interrupt is usable now; orange when it is unavailable now; orange then green along the cast timeline when the cooldown ends before the cast does. The boundary corresponds to the time the interrupt cooldown ends. Consider spell range on `focus` where the API gives a reliable, secret-safe answer, and never call an out-of-range spell green. Distinguish truly unknown/unavailable data with a configurable neutral tint instead of promising a kick.
- Expose editable preset colors for grey, green, orange, and unknown/neutral through the existing options panel. Keep palette values normalized and persistent, with sensible defaults. Do not require users to provide their own interrupt spell ID.
- Existing modifier, raid marker, channel, macro, and binding behavior must remain unchanged. Localize new setting labels for enUS, zhCN, zhTW; update README files and affected nearby design documentation when implementation changes their descriptions.

## Technical evidence and constraints

`/Users/iu/wow/EllesmereUI/EllesmereUI_Kick.lua` (`kickSpellsByClass`, `RefreshKickAbility`, `ComputeCastBarTint`) is the local reference for class/pet spellbook identification and a cooldown `DurationObject:IsZero()` with `C_CurveUtil.EvaluateColorValueFromBoolean()` instead of branching on secret values. It is a reference, not a dependency: FocusClaim must work without EllesmereUI loaded. `EllesmereUIUnitFrames/EllesmereUIUnitFrames.lua` around `UpdateUnitFrameKickTick`, `RefreshUnitFrameKickTick`, and `ApplyUnitFrameCastColor` demonstrates secret-safe cast/cooldown DurationObjects, status-bar marker placement, conditional alpha and uninterruptible overlay. `EllesmereUINameplates/EllesmereUINameplates.lua` around `_timerTick` uses `UnitCastingDuration`/`UnitChannelDuration` plus `GetRemainingDuration` and formatted text. Adapt only the necessary pieces; avoid copying large portions.

WoW 12.x may make cast timing, interruptibility, cooldown readiness, and range result secret in combat. Do not compare, branch on, or do Lua arithmetic with secret values. Use native StatusBar/DurationObject/ColorCurve/alpha mechanisms for those operations, including grey uninterruptible override and orange/green split. Guard API absence and transient misses. Range checking may need independent in-game verification; if it cannot be safely and accurately determined, show unknown rather than green. Do not turn uncertain states into false positives. Existing TOC includes 12.0.x/12.1.x interfaces: avoid assuming an API exists on every declared interface version without a fallback or appropriate guard.
